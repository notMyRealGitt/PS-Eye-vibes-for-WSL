# Agent handoff: PS Eye / WSL maintenance

This file is intended for future agents. Keep README.md focused on ordinary use.
Update the verification status after the user tests a restart. The snapshot below
records work on 2026-11-08; inspect the actual host before troubleshooting.

## Implemented setup

- Camera: PS Eye USB ID `1415:2000`; last Windows BUSID `1-6` (can change).
- Windows: installed usbipd-win 5.3.0 through winget's interactive installer.
  Shared only this camera with elevated `usbipd bind`, then attached to WSL.
  Sharing is persistent; attachment must be repeated after restart/reconnection.
- WSL: Ubuntu-24.04, Ubuntu 24.04.4, x86_64,
  `6.6.87.1-microsoft-standard-WSL2`. Microsoft kernel image retained.
- The vendor configuration omitted `USB_GSPCA_OV534`; GSPCA core, V4L2, and
  videobuf dependencies were available. Built the existing in-tree driver from
  pinned Microsoft source. No new driver/application code was written.
- Build packages installed: flex, bison, dwarves/pahole, libssl-dev, cpio,
  qemu-utils, gcc-13-plugin-dev; v4l-utils for inspection. build-essential,
  libelf-dev, Git, kmod, usbutils, FFmpeg/ffplay were already available.
  Package dependencies also updated OpenSSL. User stfn already belonged to video.
- Temporarily inserted only `gspca_ov534.ko` after `modprobe gspca_main`.
  Runtime driver `ov534` created `/dev/video0`, owned root:video mode 0660
  after udev settled. Normal-user capture succeeded.
- Device by-id path:
  `/dev/v4l/by-id/usb-OmniVision_Technologies__Inc._USB_Camera-B4.09.24.1-video-index0`.
- Persistent image contains the original stock module tree plus the tested
  driver under `updates/`, with indexes regenerated by depmod.

## Verified results and known quirks

- Camera advertises 320×240 and 640×480 YUYV and raw Bayer modes.
  Only 320×240 YUYV at 30 fps was tested; higher rates/latency are unmeasured.
- Recognizable PNG inspected. FFV1 capture: 32.000 seconds, 959 decoded frames,
  959 unique frame hashes, no identical consecutive images.
- Three zero timestamp intervals, none backwards, maximum gap 67 ms.
  Direct decode-to-null logs duplicate DTS warnings, not codec corruption.
  Strict decoding with a regular output timestamp grid has an empty error log.
  Retain the original recording/timestamps; do not describe timing as flawless.
- WSLg software preview worked. Bound a live ffplay run with external timeout;
  code 124 reflects that limit. Hardware rendering was not established.
  Use the README command without ffplay -t for interactive preview.
- First module load passed normal CRC checks but warned about split BTF metadata
  based on the rebuilt vmlinux rather than the vendor kernel. Removed only .BTF
  and .BTF.ext from a deployment copy and reloaded successfully without a new
  warning. Executable .text and imported CRCs were identical before/after.
  Keep kernel BTF/configuration enabled; never force module loading.
- Temporary, unindexed modules must be unloaded with `rmmod gspca_ov534`;
  `modprobe -r` failed to find this manual insertion before persistent indexing.
- USB/IP URB unlink status -104 occurred when capture readers closed, consistent
  with cancellation. No mid-recording USB failure was observed.
- The full build emitted two unrelated AMD KVM objtool warnings.

## Troubleshooting sequence

Check `uname -r`, Windows usbipd state, `lsusb -d 1415:2000`, `lsusb -t`,
`lsmod`, `modinfo gspca_ov534`, device identity/permissions, and fresh dmesg.
Before the first persistent activation, modinfo can fail while the manually
inserted module is present in lsmod. The stock /proc/config.gz still says the
subdriver is disabled even when an additional module is loaded.

For this exact kernel after activation, modinfo should resolve updates/.
Missing USB enumeration is an attachment issue; a driver rebuild cannot fix it.
If the node is inaccessible immediately after load, wait for udev to settle.
Use a normal shell to verify group membership and device access.

The agent sandbox previously blocked Windows interop with UtilBindVsockAnyPort
and libusb initialization with -99, and exposed altered groups/readonly mounts.
These were sandbox limitations, not camera incompatibility. Use the normal
escalation mechanism for necessary host checks. Host administration worked via
`wsl.exe --distribution Ubuntu-24.04 --user root --exec ...`; passwordless sudo
was unavailable. Never ask for or collect the user's password.

If capture works but preview fails, test display independently. The implemented
route needs no Zadig/WinUSB replacement, DirectShow filter, forwarding server,
or custom firewall rule beyond usbipd's installer defaults. Untested fallback
plans were removed; investigate new failures before choosing another route.

## Rebuild for the exact recorded kernel

This is a recipe from the successful build, not an unattended installer.
Do not execute a large rebuild just to diagnose USB attachment.
For a different kernel, choose matching source/configuration again and review
ABI requirements; this snapshot is not a generic WSL kernel configuration.

For a fresh Windows host, install with
`winget install --interactive --exact --id dorssel.usbipd-win --source winget`,
then use elevated `usbipd bind --busid ACTUAL_BUSID` once for the identified
camera. Follow README attachment steps in normal PowerShell afterward.

Install missing prerequisites from the package list above. Original build tools:
GCC 13.3.0, binutils 2.42, pahole 1.25; vendor kernel reported GCC 11.2.0.
Use a fresh build/output directory and start from the repo root:

```bash
test "$(uname -r)" = 6.6.87.1-microsoft-standard-WSL2 || exit 1
test "$(uname -m)" = x86_64 || exit 1
repo=$PWD
build="$repo/artifacts/build-6.6.87.1"
out="$repo/artifacts/rebuild-6.6.87.1"
mkdir -p "$repo/artifacts"
git clone --depth 1 --branch linux-msft-wsl-6.6.87.1 \
  https://github.com/microsoft/WSL2-Linux-Kernel.git "$build"
cd "$build"
test "$(git rev-parse HEAD)" = 7573ea4347d2adc267f3de8852ecca885ec2cc9d || exit 1
cp "$repo/config/stock-6.6.87.1.config" config.running
cp config.running .config
scripts/config --module USB_GSPCA_OV534
make LOCALVERSION= olddefconfig
scripts/diffconfig config.running .config
make -s LOCALVERSION= kernelrelease
```

Review the diff before continuing. Expected functional change:
USB_GSPCA_OV534 n -> m; toolchain capability/metadata differences were also
present in the successful build. Release must equal uname -r.
With CONFIG_MODVERSIONS=y, modules_prepare alone does not produce needed CRCs;
the original work used a full build:

```bash
make -j12 LOCALVERSION= > build.log 2>&1
test -s Module.symvers
test "$(make -s LOCALVERSION= kernelrelease)" = "$(uname -r)" || exit 1
mkdir "$out"
cp drivers/media/usb/gspca/gspca_ov534.ko "$out/gspca_ov534.with-btf.ko"
objcopy --remove-section .BTF --remove-section .BTF.ext \
  "$out/gspca_ov534.with-btf.ko" "$out/gspca_ov534.ko"
cp Module.symvers config.running build.log "$out/"
cp .config "$out/config.build"
scripts/diffconfig config.running .config > "$out/config.diff"
modinfo -F vermagic "$out/gspca_ov534.ko"
modinfo -F vermagic gspca_main
sudo modprobe gspca_main
sudo insmod "$out/gspca_ov534.ko"
sudo udevadm settle
v4l2-ctl --list-devices
```

If the module is already loaded, close readers and unload it with rmmod before
the insertion. Check dmesg for CRC/format/symbol errors; never bypass them.
Verify a still and sustained capture using the identified camera node before
persistent deployment. Example capture, preserving source timestamps:

```bash
timeout 45s ffmpeg -hide_banner -nostdin -n -f v4l2 \
  -input_format yuyv422 -video_size 320x240 -framerate 30 -i "$CAM" \
  -t 32 -an -fps_mode passthrough -c:v ffv1 "$out/test.mkv"
ffprobe -v error -count_frames -select_streams v:0 \
  -show_entries stream=width,height,avg_frame_rate,nb_read_frames:format=duration \
  "$out/test.mkv"
ffmpeg -hide_banner -v warning -xerror -err_detect explode -i "$out/test.mkv" \
  -an -vf 'setpts=N/(30*TB)' -fps_mode passthrough -f null -
```

Set CAM from the confirmed device listing (README shows this unit's by-id path).
The timestamp filter is for codec validation only, not a measurement of source
timing. Inspect the scene and motion; a valid file alone is insufficient.

After capture passes, stage the existing matching module tree and add the tested
module. Keep the stock dependencies; do not package only the camera module:

```bash
release=$(uname -r)
stock=$(readlink -f "/lib/modules/$release")
stage="$build/module-stage-stock"
mkdir -p "$stage/lib/modules/$release"
find "$stock" -mindepth 1 -maxdepth 1 \
  ! -name lost+found ! -name rw ! -name build ! -name source \
  -exec cp -a --no-preserve=ownership -t "$stage/lib/modules/$release/" -- {} +
install -Dm644 "$out/gspca_ov534.ko" \
  "$stage/lib/modules/$release/updates/gspca_ov534.ko"
depmod -b "$stage" "$release"
modinfo -b "$stage" -k "$release" gspca_ov534
bash "$repo/scripts/package-modules.sh" "$stage" "$release" "$out"
```

Copy the resulting VHDX to the Windows deployment folder, preserving any existing
deployed image before replacement. Merge config/wslconfig.example into the
current .wslconfig. Preserve other settings and record prior values.
Do not install the rebuilt bzImage: only the extra module is needed for this host.

save work and restart WSL. Preserve unrelated configuration added later.
Detach the camera with usbipd using its actual current BUSID. Elevated
